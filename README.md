# Web Sticky Scroll

[![CI](https://github.com/dongruixiao/web-sticky-scroll/actions/workflows/ci.yml/badge.svg)](https://github.com/dongruixiao/web-sticky-scroll/actions/workflows/ci.yml)

> **对外名称：TopClip — 读长文，不掉线**（命名过程与查重见 [store/naming.md](store/naming.md)）。
> 仓库名 `web-sticky-scroll` 保持不变，作为技术标识（GitHub Pages 的隐私政策链接依赖它，上架时要用）。

**TopClip —— 读长文，不掉线。**

走神的原因通常不是"找不到章节"，而是"忘了这一节在讲什么"。往下滚两屏，目光还在字上，脑子已经丢了上下文——
这节属于哪一章？作者在论证什么？这个扩展把当前章节标题**原样**钉在页面顶部（页面自己的字体、字号、字重、行高、颜色），
像给文章贴了一张一直在视线里的便利贴。所以核心是**提醒你在读什么**；导航只是顺带，进度条是增值。

它和 VS Code 的 Sticky Scroll 是同一个思路（当前作用域常驻视野），实现上不动网页一个字节：
标题被钉在页面最顶部、紧贴紫色进度线并与正文列对齐，鼠标悬停可展开完整大纲，点击即可回溯。

默认不显示文章大标题、最多保留 3 级、检测到原站自带目录时主动退让。
如果更喜欢独立、精致的悬浮控件，可以切换到液态玻璃胶囊；它支持自由拖动并按站点记住位置。

## 设计原则

1. **标题原样被吸住**：条里展示的是当前标题的克隆（DOM 结构 + 页面计算样式快照），
   不重排字号、不套自己的字体，条高跟着标题的自然行高变化——就像网页自己的标题被钉住了。
   吸顶时机只有一个判据：**标题是否已经完全滑到条的后面**（越过条顶边）。
   向下滚动时，标题必须被条完全盖住才切换，不会出现"标题还露在下面、条已经提前显示它"；
   向上回滚时，下级标题的原文一露头就退回上一级，不会出现"上级标题已在屏幕上、条还赖着下级"。
   判定只看当前几何位置，快速回滚和锚点跳转都不会残留旧状态。
2. **层级不堆在条上**：条里只放当前标题；上级层级放进悬停展开的抽屉顶部，做成一条可点击的细路径。
3. **中性全宽液态玻璃**：无痕模式不再提取网页背景色，使用受控的浅色 / 深色玻璃表面；
   高度严格等于标题行高，不增加额外 Toolbar 空白。
4. **标题排版取自页面**：字体、字号、字重和行高来自原网页标题；玻璃表面统一使用可读前景色。
   阅读进度使用固定在视口顶部的 1px 紫色品牌线，不依赖页面配色。
5. **不与原站争**：原站目录在屏幕上时，插件退化成「当前小节」指示器，不再弹自己的大纲。
6. **不改页面视觉与布局**：不写页面样式类、不插入占位元素，全部 UI 挂在独立 Shadow DOM 里；
   少量用于诊断和清理的 `data-wss-*` 标记会在退出时全部移除。
7. **宁可错杀，不要错误展示**：标题尺寸、列位置或叠置关系无法可靠确认时不激活；
   连续运行异常会熔断并彻底退出，不留下半截界面，也不持续打扰页面。

## 功能

功能按重要性分三层：

**核心：内容锚点**

- **当前章节标题常驻**：标题原样钉在顶部（同字体、同字号、同颜色），条高随标题自然高度变化

**顺带：导航**

- **悬停展开大纲**：按标题树嵌套显示、带层级引导线，当前小节高亮；顶部一行是可点击的上级路径
- **一键回溯**：点击任意层级平滑跳转，落点正好停在标题下方
- **点击标题可钉住目录**：方便通读全文结构，点空白处或 `Esc` 收起

**增值**

- **整篇阅读进度**：固定在页面最顶部的 1px 紫色细线显示已读比例——0% 从正文顶部开始，读到页面末尾即为 100%
- **原站目录自适应**：页面自带目录可见时自动退让，不重复打扰
- **两种形态**：无痕阅读（默认，中性全宽液态玻璃）与液态玻璃胶囊（可自由拖动并记住位置），随时可切
- **跟随页面配色**：底色与字色采样自页面，深色站点自动深色
- **站点规则**：支持黑名单 / 白名单，可在当前站点一键禁用
- **快捷键**：`Alt+[` / `Alt+]` 跳到上一节 / 下一节；`Alt+Shift+S` 切换当前站点，
  `Alt+Shift+W` 切换全局开关
- **本地诊断**：popup 可复制页面 URL、激活原因、标题结构指标、停靠位置与层级；
  只复制到剪贴板，不发送网络请求

## 显示策略

遮挡问题不是靠调透明度解决的，而是靠「什么时候该出现」：

| 策略 | 行为 | 适合谁 |
| --- | --- | --- |
| 常驻（默认） | 一直贴在顶部，和 VS Code 一样随时可见 | 大多数人 |
| 智能 | 向下滚动浮现；向上滚动收起；静止 2.6s 后淡到 45%，悬停/聚焦即恢复 | 不想在回看时被顶部条分心 |
| 轻提示 | 只在滚动时出现，停手 1.6s 后完全收起 | 极度在意遮挡的人 |

> 通过面包屑主动跳转时，智能策略会临时保持可见 1.6s——否则你点一下，工具自己就消失了。

## 激活范围：只在“真的能读”的页面上出现

插件在所有 http/https 页面都会加载，但**只有判定为长文/文档的页面才会真的显示**。
判定基于页面结构而不是域名白名单，主要看这些指标（判定依据会写在正文容器的
`data-wss-stats` 上，方便排查“为什么这页没激活”）：

| 指标 | 作用 |
| --- | --- |
| 有效标题数、段落文字量 | 太短、太少 → 不激活 |
| **链接文字占比 > 55%** | 文字大多在链接里 → 导航/营销首页/搜索结果，不激活 |
| **段落文字占比 < 40%** | 正文块太少（卡片、表格、图墙）→ 不激活 |
| **有效标题占全页比例 < 25%** | 列表页里的一张卡片 → 不激活 |
| 最长小节 / 层级嵌套 | 都要足够深，否则当成目录页/聚合页 → 不激活 |
| **持续对话输入区 + 多轮消息结构** | AI 聊天、代理工作区、对话式搜索 → 整体静默，不把单条回答当文章 |
| **中性玻璃表面** | 不读取网页背景色；渐变、图片和深色页面同样使用固定可读玻璃表面 |
| 兜底到 body 的页面额外要求标题排在同一列 | 排除多栏营销页 |
| 侧栏/导航里“标题后面没有正文”的项 | 直接不进大纲（例如 GitHub 仓库页侧栏） |

正文长度统计会**跳过内联 `<script>`/`<style>`**：Next.js、Nuxt 这类站点会把整页数据塞在
脚本里，否则会被误判成“十万字正文”。

实测（`npm run field-check`，27 个真实站点，可复跑；其中 16 个应激活、11 个应静默）：

| 站点 | 期望 | 结果 |
| --- | --- | --- |
| MDN / Python / React / Wikipedia / Vite / web.dev / TypeScript / Rust Book | 激活 | ✓ 全部激活，对齐偏差 0px |
| GitHub README / WHATWG HTML / W3C WCAG / Martin Fowler / ar5iv / Cornell LII / pi.dev | 激活 | ✓ 结构正确；pi.dev 这类整宽容器也能对齐正文列 |
| Hacker News / MDN 目录 / DuckDuckGo / GitHub Trending / npm Search / Wikipedia Category / YouTube 首页 / Apple 首页 | 静默 | ✓ 全部静默 |
| ChatGPT / Gemini 对话页面 | 静默 | ✓ 不按域名排除，由持续对话与输入区结构共同判定 |
| Paul Graham 无小节标题长文 | 静默 | ✓ 没有可吸顶的对象，明确不展示 |
| Tailwind 首页 | 边界情况 | 它是 6.7k 字、单栏、段落为主的长营销页，结构上与长文一致 → 判定激活 |

实地检查同时要求：插件造成的布局位移为 0、显示页面的标题与正文列偏差 ≤2px；
滚动期间的长任务会记录在报告中，但真实站点自身造成的长任务无法可靠归因给扩展。

想要更严格的控制，有两级手动开关：

- **设置 → 站点规则**：改成「仅在下列网站生效」，插件就只在你指定的站点工作
- **popup**：对当前站点一键「在此站点禁用」；在没激活的页面上可以「强制启用」（判定失败时的兜底）

## 适用场景（含实测结果与不适用的情况）

| 场景 | 状态 |
| --- | --- |
| 技术文档（MDN / Python / React / Vite） | ✅ 实测正确激活 |
| 学术论文 HTML 版（arXiv / ar5iv） | ✅ 实测正确激活（识别 `article.ltx_document`，索引 23 个章节标题） |
| 法律条文（结构清晰的条文页，如 Cornell LII） | ✅ 实测正确激活 |
| Wikipedia / GitHub README | ✅ 实测正确激活 |
| 中文长文（知乎、公众号等） | ⚠️ 部分站点有登录墙/反爬，需在真实浏览器确认；判定失败时可在 popup 里「强制启用本页」 |
| 列表页 / 搜索结果 / 营销首页 | ✅ 实测保持静默 |
| **PDF（含 arXiv 的 PDF 版）** | ❌ 不支持：Chrome 的 PDF 阅读器不在网页 DOM 里，扩展无法介入 |
| 没有小节标题的长文（不少新闻与深度报道） | ❌ 没有可吸顶的对象，保持静默 |

一句话：**适用于"网页里带章节结构的长文"**；有没有目录都行（有目录时自动让位），但没有小节标题或不是网页正文时，它不会有任何动作。

## 交互

- **悬停**无痕标题或液态玻璃胶囊 → 展开文章目录；大标题下方不会出现"两套目录打架"的情况（原站目录可见时自动退让）
- **点击无痕标题或液态玻璃胶囊** → 把目录钉住，鼠标移开也不收起；再次点击、点击页面其它地方或按 `Esc` 关闭
- **目录面板**：顶部是标题「文章目录」与整篇进度，然后是当前路径，下面是按标题树嵌套的层级大纲
  （带层级引导线；当前小节主色高亮 + 圆点加重，路径层级淡化，其它层级更淡）
- **点击任意层级** → 平滑跳转到该小节，落点正好停在「它吸顶后的位置」，所以跳转后标题不会藏在条后面

层级可裁剪（1～6 级）、可隐藏文章大标题、超长标题按级截断并附完整 Tooltip。

## 面包屑层级规则

- 默认**不显示文章大标题**（h1 根级），需要时可以关掉这条规则
- 默认**最多显示 3 级**，超出部分折叠为 `…`，悬停胶囊时展开完整路径
- 路径通过标题树的父子链推导（h1 › h2 › h3 › h4），不会出现跨级错配
- 全部层级被裁掉时至少保留当前小节，永远不会出现空胶囊

## 原站目录适配

插件会扫描页面中的目录容器（`nav` / `aside` / `[class*="toc"]` 等，或包含 ≥3 个指向正文标题的锚点的容器），
并判断它**此刻是否真的在屏幕里**：

- 目录可见 → 胶囊退让为「当前小节」指示器，不再弹自己的大纲，避免两套目录互相打架
- 目录滚出屏幕 → 自动恢复完整功能（悬停大纲、多级路径）
- 不想要这套行为，可以在设置里选「保持完整功能」

## 设置项

| 分组 | 设置 | 默认值 |
| --- | --- | --- |
| 基础 | 启用、外观形态（无痕阅读 / 液态玻璃）、无痕标题宽度、玻璃初始位置、主题、垂直微调 | 启用 / 无痕阅读 / 满宽 / 顶部居中 / 跟随系统 / 0px |
| 显示 | 显示策略、不显示文章大标题、最多显示层级、原站已有目录时 | 常驻 / 开 / 3 级 / 自动退让 |
| 站点规则 | 生效范围（全部 / 黑名单 / 白名单）+ 域名列表 | 全部网站 |
| 数据 | 导出 / 导入 JSON、恢复默认 | — |

设置写入 `chrome.storage.sync`（跨设备同步），并带有版本迁移与越界值修正：
旧版本的配置会被自动升级，不会因为字段缺失而失效。

## 边界情况

| 问题 | 处理方式 |
| --- | --- |
| 原站固定导航栏 | 无痕标题固定在页面最顶部；液态玻璃胶囊自动贴到站点导航栏下方，另有像素级垂直微调 |
| 单页应用路由变化 | `MutationObserver` 监听 DOM 重建 + 轮询 `location.href` 感知 `pushState` |
| 标题缺少 id | 提取阶段生成 `data-wss-id` 占位标识，跳转走 `scrollIntoView` |
| 标题过长溢出 | 单级 `max-width: 180px` + 省略号，`title` 保留完整文本 |
| 侧栏 / 页脚 / 评论区标题干扰 | 正文容器启发式识别 + 过滤 `nav / aside / footer / role=* / 评论区` |
| 目标站样式污染 | UI 挂在独立 Shadow DOM，宿主页面 CSS 命中不到 |
| 列表页 / 搜索结果误触发 | 智能阅读模式判定：需要足够长的正文小节，或「有层级 + 小节水位足够深」 |
| AI 聊天 / 代理页面误触发 | 同时检测持续对话轮次与底部或固定输入区；任一侧证据不足都不排除，评论区、搜索框和单条 AI 摘要不会单独触发 |
| 文章卡片列表页 | 通过「选中容器占全页比例」与「小节水位」双重排除 |
| 页面触底 | 只在文档真正无法继续滚动时让最后一个标题接替；此前仍严格按越过吸顶线判定，不提前展示中途可见标题 |
| 滚动容器而非 window 的站点 | 用标题的视口位置推断滚动方向，不依赖 `window.scrollY` |
| 用户想临时看全部结构 | 悬停展开折叠层级 + 大纲抽屉；`Esc` 关闭 |
| 站点顶栏随滚动隐藏 / 出现 | 每 800ms 重新校准液态玻璃胶囊的避让位置；无痕标题始终紧贴页面顶部 |
| 正文里的粘性元素（小节吸顶头、粘性工具条） | 属于内容，一律不参与「避让顶栏」的计算——否则条会跟着它们掉到页面中间 |
| 固定侧栏 / 全高固定容器 | 宽度不足视口 60% 的固定元素不算顶部导航条，直接忽略 |
| 顶部出现遮罩层 / 对话框 | 覆盖大半个屏幕的实心遮罩会触发收起，不浮在对话框上面 |
| 浏览器页面查找（Ctrl/⌘+F） | 检测到查找快捷键立即收起——不压住查找条，也不挡住被滚到顶部的命中文字；按 `Esc`、回到页面里点击、或 20 秒兜底后恢复 |
| 站点搜索面板（Cmd+K）/ 对话框 | 检测到盖住顶部的 `dialog / aria-modal / role=dialog` 时自动让位，关闭后恢复 |
| 其它扩展 / 站点注入的高层浮层 | 读取顶部实际层级；若对方比我们更高，就自动降到它下面，不使用“绝对最高”硬盖 |
| 标题散落在多栏、隐藏副本重叠、尺寸为零 | 几何可靠性门禁拒绝激活，宁可整页不显示 |
| 连续布局或渲染异常 | 10 秒内连续 3 次失败即熔断，销毁 UI、监听器、计时器和页面标记；本页会话不再重试 |
| Web 字体晚到 | 字体加载完成后重新克隆当前标题，避免无痕标题继续使用旧字体快照 |
| 页面没有可靠底色 | 中性玻璃不需要网页底色；标题排版仍取自页面，前景色由玻璃主题保证 |
| 背景运行中变成渐变 / 图片 | 不影响标题显示；玻璃表面和紫色进度保持稳定 |
| 正文列很窄或页面全宽 | 列宽不足 260px 时退回默认内边距，文字仍对齐可见区域 |
| 正文容器把侧栏也框进去（整宽 `main`） | 正文列不从容器矩形取，而是**从内容本身推导**：标题左缘与段落左缘一起取中位数（单边异常由多数票纠正），右缘取同列段落的中位数；都不可信时回退到容器内容盒 |

## 隐私

- 不发送任何网络请求，不接入遥测与统计
- 只使用 `storage` 权限存放设置；不申请 `tabs`、`history`、`<all_urls>` 之外的任何权限
- 页面内容只在本地 DOM 中读取，标题文本不会离开浏览器

## 开发

- **不想编译**：到 [Releases](https://github.com/dongruixiao/web-sticky-scroll/releases) 下载 `web-sticky-scroll-<版本>.zip`，
  解压后到 `chrome://extensions` 开启开发者模式 →「加载已解压的扩展程序」→ 选解压出来的文件夹即可

```bash
npm install

npm run dev          # CRXJS 开发模式（HMR），在 chrome://extensions 加载 dist/
npm run build        # 类型检查 + 打包到 dist/
npm test             # 单元测试（启发式判定、路径裁剪、设置迁移）
npm run e2e          # 端到端：真实浏览器加载 dist/ 跑 47 项断言
npm run field-check  # 实地检查：27 个真实站点的激活范围、对齐与插件布局位移
npm run demo:dev     # 本地演示页

```

加载扩展：`chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选择 `dist/`。

`npm run e2e` 需要一个支持 `--load-extension` 的浏览器：默认使用 Playwright 自带的 Chromium
（`npx playwright install chromium`），也可以用 `WSS_CHROME_PATH=/path/to/chrome npm run e2e` 指定
Chrome for Testing / Chromium。Chrome 137+ 正式版已经移除命令行加载未打包扩展的能力，因此不要指向它。

端到端覆盖：注入与挂载、顶部静默、固定顶栏避让、默认隐藏大标题、吸顶时机、原站目录退让与恢复、
点击回溯落点与跟随、键盘跳转、外来浮层礼让、异常熔断、popup / options 渲染、设置实时同步。

## 已知取舍

- **AI 小节摘要**（设计文档 V2）未实现：需要外部模型服务与 API Key，属于独立工作项
- 没有实现「插入占位元素把正文推下去」的方案：那会改变宿主页面布局，风险大于收益
- 目前文案为中文；多语言（`_locales`）留到接入英文用户时再做

关于遮挡：默认形态使用与标题同高的中性全宽液态玻璃，不读取网页背景色；
页面最顶部保留 1px 紫色阅读进度线。液态玻璃胶囊可自由拖动，靠近视口边缘会自动留出安全距离，
并按站点记住位置。主动展开的大纲使用扁平页面底色，没有毛玻璃和重阴影。
标题高度仍跟随网页原始标题，因此不会为了变薄而改写原网页字号。

标题克隆是「只读」的：我们克隆 DOM 并把计算样式写成内联样式，页面里的原始标题不移动、不改样式；
因此站点自己的悬停效果、锚点行为在原文里仍然照旧，无痕标题只负责长相一致与被点击回溯。
